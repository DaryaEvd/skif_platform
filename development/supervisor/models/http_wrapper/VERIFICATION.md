## Что выполнено

Docker daemon доступен после разрешения доступа к сокету. Оба API-образа собраны
из текущих исходников. Сначала пробовался большой GCC base image; итоговый C
Dockerfile использует компактный Python/Debian builder с gcc и отдельный runtime.

Реально выполнены:

1. Реальные Python и C через HTTP внутри Docker, с портами localhost 18081/18082.
2. Readiness, отклонение неверного входа, принятие запуска, опрос статуса.
3. Повтор runId после успеха: один процесс по журналу; результат неизменен.
4. Изменённый запрос и новый runId отклонены с 409.
5. Получение метаданных, полного результата, логов и пустого журнала публикаций.
6. Проверка SHA-256 и размера скачанного результата; повторное скачивание.
7. 11 автоматических тестов локально и 11 внутри Docker: все прошли. Покрыты
   конкурентные POST, ненулевой exit, SIGKILL, отсутствие результата, неверный JSON,
   NaN, неверная матрица, доступность статуса во время работы, отмена процесса
   с дочерним процессом, отмена во время FINALIZING без позднего SUCCEEDED.
8. Настоящий C binary: отсутствующий вход, недоступный путь end.json,
   недоступный путь error_rate.json — во всех трёх случаях exit code 1.
9. Прямой файловый запуск Python и C без API в тех же Docker-образах:
   оба завершились с кодом 0, Python дал совпадающий результат, C — матрицу 988×988.
10. Дополнительно C собран локальным компилятором и выполнен напрямую успешно.

Тесты с HTTP-сокетами сначала были запрещены sandbox и не выполнились; после
предоставления разрешения повторены успешно. Это не ограничило итоговые проверки.
Обязательных проверок, которые не удалось выполнить, нет. Отмена долгой реальной
C-модели отдельно не проверялась: для проверки отмены использован разрешённый
отдельный процесс с потомком. Исходные Dockerfile отдельно не пересобирались;
прежний файловый способ запуска проверен с binary/script из API-образов.

## Текущие границы

Один процесс API обслуживает один расчёт; восстановления после перезапуска нет.
Существующие модели не публикуют промежуточные значения, поэтому API честно
возвращает пустую историю. Логи дублируются в памяти и на диске; для длительных
шумных моделей потребуется дисковая пагинация. Процессы существующих моделей
и тестовый потомок завершаются через POSIX process group; изоляция произвольных
программ, намеренно покидающих эту группу, на этом этапе не реализована.
